# 播浪

中文名：**播浪** · 前缀 `livewave` · 端口 **6400 / 11400**

## 骨架

**互动事件入流 → 处理时乱序缓冲排序 → 事件时间水位线批量推进 → 热度窗关闭发射 → 迟到修正/撤回 → 窗输出与撤回互证**

皮：直播间点赞/送礼互动。去皮是事件时间窗计算 + 允许迟到与撤回，不是直播运营后台 CRUD，不是点击会话空闲切开。

## 处理时乱序缓冲（乙口径）

「乱序如何推进」全局只贯彻一种口径：**处理时缓冲排序再推进**（站规 `乱序处理策略`）。

- 同房事件先入 `乱序缓冲`，**绝不按到达序立即抬水位**；
- 释放时按 **事件时升序** 逐条处理、批量抬水位，故「先到处理时晚事件、后到处理时早事件」的早事件不会被晚事件抬起来的水位误旁路；
- 缓冲释放与水位推进在**同一事务**（`BEGIN IMMEDIATE`）内，二者同成败，禁止「先抬水位再丢早事件」；失败整体回滚，不留半截；
- 释放策略（站规）：请求冲刷 / 缓冲深度 ≥ `缓冲批量` / 最老缓冲处理时滞后 ≥ `缓冲超时秒`。

只读接口 `GET /api/乱序缓冲`：每房 **缓冲深度 / 释放水位 / 旁路集（乙实际 vs 甲反事实）/ valid**。
旁路一律以「释放前水位」判定越界（`依据` 记入旁路匣），并在 `缓冲释放` 表同时记录乙实际与甲反事实旁路集，使两口径可区分。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6400
# 事件流依次灌「准时热度样例」→「迟到修正样例」→「超迟到旁路样例」
#   →「处理时乱序样例」（乙口径下早事件仍入窗）→「缓冲释放关窗并发样例」（不得半截）
# 再跑「窗互证」：窗合计 ↔ 事件合计 ↔ 末次撤回 ↔ 缓冲 valid
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 互动事件 | 带事件时/处理时的点赞送礼 |
| 乱序缓冲 | 同房事件按处理时先入缓，释放时按事件时排序批量推进 |
| 缓冲释放 | 每次释放的水位前后、排序后事件、乙实际/甲反事实旁路集 |
| 水位线 | 每房事件时水位 + 允许迟到秒 |
| 热度窗 | 翻滚窗；开启累计，关闭发射 |
| 撤回单 | 已关闭窗被允许迟到事件修正 |
| 旁路匣 | 超允许迟到 |
| 窗贯验 | 窗合计 ↔ 事件合计 ↔ 末次撤回 ↔ 缓冲不得半截 |
